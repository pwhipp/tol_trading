# Trading Orchestration Language (TOL)

A deterministic, human-readable orchestration language for executing
multistep trades safely, with an implementation using Interactive Brokers API.

## Why this exists

Interactive Brokers provides powerful tools (TWS, Basket Trader, API),
but complex trade sequences remain fragile:

-   Selling one instrument and then buying another with the proceeds is
    unreliable
-   TWS restarts can silently drop dependent orders
-   Basket Trader is stateful and brittle
-   There is no durable, reviewable representation of *intent*
-   Partial execution failures are hard to reason about or recover from

TOL exists to solve this problem.

TOL provides:

-   A reviewable contract of intent
-   Crash-safe orchestration
-   Dependency-driven execution
-   Deterministic behaviour
-   A human auditable structure that can be generated by humans, UIs, or AI.

TOL is deliberately boring. That is its strength.

### What TOL *is*

-   A declarative orchestration language
-   Deterministic and resumable
-   Human-readable and auditable
-   Focused on *execution safety*

### What TOL *is not*

-   A trading strategy language
-   A scripting language
-   A decision engine
-   A place for conditionals or indicators

All decision-making happens outside TOL. TOL expresses and executes decisions that
have already been made.

## Core principles

1.  Declarative intent. Describes what should happen, not how to
    compute it.
2.  Deterministic execution. The same TOL document always produces
    the same orchestration.
3.  Dependency-driven ordering. Execution order is inferred from
    explicit references.
4.  Crash safety. Every action has a stable identity and lifecycle.
    Execution can resume safely after interruption.
5.  No conditionals, No branching, comparisons, loops, or indicators.

## High-level model

A TOL document describes a **directed acyclic graph (DAG)** of actions.

-   Each action has a unique ID
-   Dependencies are inferred from references
-   Independent actions may execute concurrently
-   Dependent actions wait automatically

Execution order is derived, not written.
